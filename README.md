# 游戏对话与任务编辑台

面向本地单机使用的对话命令行工具。当前版本提供对话文件校验、单步分支预览，
以及节点查看、入向引用查询、不可达节点报告三种只读查询；所有命令都不写回
输入文件。

## 环境与依赖

- 仅依赖 Python 3 标准库，无需联网、无需安装第三方包、无需数据库初始化。
- 程序只处理 UTF-8 编码的 JSON 对话文件。
- 以下功能尚未实现：任务编辑、变量条件、编辑历史、SQLite 保存。

## 对话数据的组织

仓库中的 `sample.json` 是一个岔路口示例，顶层包含两个字段：

- `start`：起始节点的编号，例如 `"start"`。
- `nodes`：节点数组。每个节点保存三项内容：
  - `id`：节点编号；
  - `text`：节点文字；
  - `options`：选项数组，每个选项有自己的 `text`，其 `target` 指向目标节点
    的编号。

示例中起始节点提供“向左走”（`target` 为 `forest`）和“向右走”
（`target` 为 `river`）两个选项；`forest` 与 `river` 的 `options` 都是空数组，
表示这两个节点是对话结尾。

编号与选项编号的规则：

- 节点编号、`start` 和选项 `target` 都必须是至少含一个非空白字符的字符串，
  并按原字符串精确匹配（首尾空白不做裁剪）。
- 选项编号从 1 开始，按 `options` 数组中的顺序确定：数组第 1 项即选项 1。

## 入门：一次校验与一次分支预览

在项目目录下依次执行以下两条命令。

校验整份对话数据：

```sh
python dialogue.py validate sample.json
```

标准输出只有一行：

```
校验通过
```

从起始节点选择选项 1，预览下一步：

```sh
python dialogue.py preview sample.json --choice 1
```

标准输出只有目标节点的文字一行：

```
你到了森林。
```

两次执行成功时退出码均为 0，标准错误为空，且输入文件的字节保持不变。

`preview` 只取下一节点的文字并输出，不真正“走”到该节点，也不保存游玩进度。
省略 `--node` 时从 `start` 指向的起始节点出发；显式指定
`--node <节点编号>` 时从对应节点出发，例如：

```sh
python dialogue.py preview sample.json --choice 1 --node start
```

## 其他只读查询

- `inspect`：查看一个节点的编号、文字和全部选项；省略 `--node` 时查看
  起始节点，只查看、不选择选项。
- `references`：查询直接指向某节点的入向引用（即各节点选项中 `target`
  等于该编号的选项）；省略 `--node` 时查询起始节点，不展开间接引用。
- `unreachable`：报告无法从 `start` 沿选项 `target` 到达的节点，起始节点
  本身始终算可达。

三条命令的完整参数与输出格式细节见 `REFERENCES.md`，各命令的测试覆盖与
回归测试运行方式见 `TESTING.md`。

## 错误说明

以下情况都会失败：文件无法读取、文件内容 UTF-8 解码失败、JSON 语法错误、
数据结构或节点引用非法、预览时选项编号越界。失败时统一表现为：

- 退出码为 2；
- 标准输出为空；
- 标准错误只有一条中文说明，不输出调用栈。

其中 JSON 语法错误的说明包含行号与列号；字段错误（如缺少 `text`）和引用
错误（如 `target` 指向不存在的节点）包含对应定位，例如
`nodes[0].options[1].target`。在示例上选择不存在的选项 3：

```sh
python dialogue.py preview sample.json --choice 3
```

会提示有效选项编号范围为 1 到 2（起始节点只有两个选项）。

`preview` 与三种查询在输出结果前都会先校验整份数据：即使错误位于不可达
节点、或位于本次未选中的分支，同样会阻止结果输出。反过来，合法的循环
引用不会导致校验失败；存在不可达节点本身也不是校验错误，只是会被
`unreachable` 报告出来。
