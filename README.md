# 游戏对话与任务编辑台

本地单机使用的游戏对话命令行工具。当前已实现对话文件的整份校验、单步
分支预览、五种只读查询，以及把结果输出到标准输出的节点重命名、单个
选项目标重定向与单个节点正文修改；任务编辑等写入文件的功能尚未实现
（见文末「尚未实现」）。

程序只处理 UTF-8 编码的 JSON 对话文件，仅依赖 Python 3 标准库，无需联网、
无需安装第三方包，也不需要数据库初始化。

## 对话数据的组织（以 sample.json 为例）

`sample.json` 是一个岔路口对话：

- 顶层字段 `start` 的值是起始节点的编号，样例中为 `"start"`。
- 顶层字段 `nodes` 是节点数组；每个节点包含：
  - `id`：节点编号；
  - `text`：节点文字；
  - `options`：选项数组，每项包含选项文字 `text` 和目标节点编号 `target`。
- 选项的 `target` 指向另一个节点的 `id`。样例中起点的两个选项分别指向
  `forest`（森林）和 `river`（河边）。
- `options` 为空数组表示该节点是对话结尾，样例中的 `forest` 与 `river`
  都是结尾节点。

编号规则：

- 节点编号是至少含一个非空白字符的字符串，查找时按原字符串精确匹配，
  首尾空白不会被裁剪。
- 选项编号从 1 开始，按 `options` 数组的顺序确定：样例起点的「向左走」
  是 1，「向右走」是 2。

## 快速开始

在项目目录下依次执行下面两条命令。

**1. 校验对话文件**

```sh
python dialogue.py validate sample.json
```

标准输出只有一行：

```
校验通过
```

退出码为 0，标准错误为空。

**2. 预览一个分支**

```sh
python dialogue.py preview sample.json --choice 1
```

标准输出只有所选选项指向的下一节点文字加换行：

```
你到了森林。
```

退出码同样为 0，标准错误为空。两次运行都不会改动 `sample.json`，
文件字节保持不变。

## 单步预览

```
python dialogue.py preview <文件路径> --choice <选项编号> [--node <节点编号>]
```

- 预览只取下一节点（所选选项 `target` 指向的节点）的文字并输出，不输出
  其他内容。
- 省略 `--node` 时从 `start` 指向的起始节点出发；显式指定 `--node` 时
  从对应编号的节点出发，编号按原字符串精确匹配。
- 预览是只读的：只看一步，不连续前进，也不保存任何游玩进度。

## 其他只读查询

- `inspect`：查看一个节点的编号、文字和全部选项（省略 `--node` 时查看
  起始节点），不选择选项。
  `python dialogue.py inspect <文件路径> [--node <节点编号>]`
- `references`：查询直接指向某节点的入向引用（省略 `--node` 时查询起始
  节点），逐项列出来源节点、选项编号与选项文字，不展开间接引用。
  `python dialogue.py references <文件路径> [--node <节点编号>]`
- `unreachable`：报告无法从 `start` 沿选项 `target` 到达的节点编号
  （起点本身始终可达）。
  `python dialogue.py unreachable <文件路径>`
- `no-ending`：报告能从 `start` 沿选项 `target` 到达、却不存在任何有限步
  路径走到结尾（`options` 为空数组的节点）的节点编号；结尾本身按零步到达
  处理，不可达节点不列入。节点只要存在一条到结尾的路径就不报告，即使其他
  选项会进入循环；整份文件没有结尾时报告全部可达节点。
  `python dialogue.py no-ending <文件路径>`
- `route`：查询从 `start` 到指定节点的路线，输出依次经过的来源节点、
  选项编号与目标节点；经过选项数量最少者优先，并列时取完整选项编号
  序列数值字典序最小者。目标就是起点时路线为空数组，目标不可达时路线
  为 `null`（仍属成功）。只接受一个文件路径加一次分写的 `--node`。
  `python dialogue.py route <文件路径> --node <目标编号>`

以上查询与预览的更多行为细节见 [REFERENCES.md](REFERENCES.md)；
全部命令的回归测试说明与运行方式见 [TESTING.md](TESTING.md)。

## 节点重命名

```
python dialogue.py rename-node <文件路径> --node <旧编号> --to <新编号>
```

- 先完成与 `validate` 相同的整份校验（不可达节点中的错误同样先报出），
  再把指定节点的 `id` 改为新编号：`start` 等于旧编号时同步更新，整份
  对话中所有等于旧编号的 `options[].target` 一并更新——不可达来源、
  同一来源的多个选项、自引用与循环中的引用都覆盖，循环不影响命令结束。
- 节点与选项数组顺序、全部文字及额外字段的 JSON 值保持原样，即使这些
  值碰巧等于旧编号也不替换；旧编号与新编号均按原字符串处理，不裁剪
  首尾空白。
- 新编号至少含一个非空白字符，且不能占用其他节点的编号；新旧编号完全
  相同时成功输出与原对象等价的 JSON。
- 成功时标准输出为修改后的完整对话对象（单行 JSON 加一个结尾换行，
  中文不转义），退出码 0，标准错误为空；输入文件字节保持不变，也不
  创建结果文件。
- 只接受上述固定参数顺序：缺少、重复、多余、连写（`--node=编号`）或
  顺序错误的参数，以及以减号开头的文件路径，都在读取文件前以上述命令
  形式原文拒绝。旧节点不存在沿用「文件中不存在编号为 … 的节点」，
  新编号为空白或与其他节点冲突时分别报告「新编号必须包含非空白字符」
  与「新编号已被其他节点使用」。

## 单个选项目标重定向

```
python dialogue.py retarget-option <文件路径> --node <来源编号> --choice <选项编号> --to <目标编号>
```

- 先完成与 `validate` 相同的整份校验（未选中的分支与不可达节点中的错误
  同样先报出，待改选项自身的悬空 target 也先报校验失败），再只把来源
  节点 `options` 中指定选项的 `target` 改为新目标编号，其他一律不动。
- 选项编号从 1 开始，按来源节点 `options` 数组的顺序确定，整数解析
  规则与 `preview` 相同；来源与目标编号均按原字符串精确匹配，不裁剪
  首尾空白，形似选项的编号值也照常处理。
- 不可达的来源或目标仍可使用，允许自引用与合法循环；新目标与原
  `target` 相同时也成功，输出与原对象等价的 JSON。
- 成功时标准输出为修改后的完整对话对象（单行 JSON 加一个结尾换行，
  中文不转义），退出码 0，标准错误为空；除选中项的 `target` 外，
  `start`、节点编号、全部文字、其他引用、所有额外字段的 JSON 值及
  节点与选项数组顺序都保持原样。输入文件字节保持不变，也不创建
  结果文件。
- 只接受上述固定参数顺序：缺参、重复、多余、顺序错误、连写
  （`--node=编号`、`--choice=1`、`--to=编号`）或减号开头的文件路径，
  都在读取文件前以上述命令形式原文加换行拒绝。整份读取、解码、JSON
  语法与校验失败沿用 `validate` 的错误结果；随后依次检查来源节点、
  整数解析、结尾节点、选项范围、目标节点，失败即停止。来源或目标
  节点不存在沿用「文件中不存在编号为 … 的节点」，选项解析失败、
  结尾无选项及越界沿用显式 `--node` 的 `preview` 对应错误。

## 单个节点正文修改

```
python dialogue.py set-node-text <文件路径> --node <节点编号> --text <新正文>
```

- 先完成与 `validate` 相同的整份校验（不可达节点中的错误同样先报出，
  不能借替换正文绕过原文件校验），再只把指定节点的 `text` 替换为新
  正文，其他一律不动。
- 节点编号按原字符串精确匹配，不裁剪首尾空白；起点、结尾与不可达节点
  都可修改，自引用与合法循环不影响命令结束。
- 新正文按传入字符串原样保存：允许空字符串、纯空白、中文、引号、
  反斜杠与换行，不解释为 JSON、文件路径或指令，形似参数的编号与正文
  也作为值处理；新正文与原值相同时也成功，输出与原对象等价的 JSON。
- 成功时标准输出为修改后的完整对话对象（单行 JSON 加一个结尾换行，
  中文不转义，正文中的换行按 JSON 规则转义），退出码 0，标准错误为
  空；除选中节点的 `text` 外，`start`、节点编号、全部选项、其他节点
  文字、各层额外字段的 JSON 值及节点与选项数组顺序都保持原样。输入
  文件字节保持不变，也不创建结果文件。
- 只接受上述固定参数顺序：缺参、重复、多余、顺序错误、连写
  （`--node=编号`、`--text=正文`）或减号开头的文件路径，都在读取文件
  前以上述命令形式原文加换行拒绝。整份读取、解码、JSON 语法与校验
  失败沿用 `validate` 的错误结果；节点不存在沿用「文件中不存在编号
  为 … 的节点」。

## 错误处理

下列失败情况统一以退出码 2 结束，标准输出为空，标准错误只输出一条中文
说明，不输出调用栈：

- **文件无法读取**（如路径不存在）：报告无法读取文件及系统原因。
- **UTF-8 解码失败**：报告文件不是合法的 UTF-8 编码。
- **JSON 语法错误**：报告中包含出错的行号与列号。
- **结构与引用非法**：如缺少字段、节点编号重复或为空、`start` 或某个
  `target` 指向不存在的节点等；说明中包含对应定位，例如 `nodes[1].id`、
  `nodes[0].options[1].target` 或 `start`。
- **预览选择越界**：例如对样例执行
  `python dialogue.py preview sample.json --choice 3`，标准错误为
  `--choice 3 不在起点 'start' 的有效选项编号范围 1 到 2 内`。

校验范围说明：

- 预览与五种查询在输出结果前，都会先对整份数据完成与 `validate` 相同的
  校验。即使错误位于不可达节点，或位于本次没有选中的分支，仍然会阻止
  结果输出。
- 合法的循环引用不会导致校验失败；存在不可达节点本身也不会导致校验失败
  （不可达节点可用 `unreachable` 查看），但不可达节点内部的结构或引用
  错误同样会使整份校验失败。

## 尚未实现

任务编辑、变量条件、编辑历史以及基于 SQLite 的保存功能尚未实现。
当前所有命令都不会改写输入文件；rename-node 的重命名结果、
retarget-option 的重定向结果与 set-node-text 的正文修改结果都只写到
标准输出，由调用方自行决定是否保存。
